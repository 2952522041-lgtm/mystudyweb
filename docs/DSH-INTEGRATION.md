# DeepSeek Harness 后台接入

设置中的“AI 执行后端”可在 API / DeepSeek Harness（DSH）之间切换，默认 API。以下行为与当前代码对应；历史联网测量单列在末尾，不代表本轮构建已经安装或完成真实模型验收。

## 范围

- DSH 默认接管 PDF 分块、文档/课程整理。设置“所有 AI 任务统一走 DSH”后，整文问答、页面/图片问答、OCR 和翻译全部经后台执行。旧设置不会被自动扩大范围。页语仍负责分批、证据来源校验、截断恢复和原子保存。
- 执行后端和模型独立：知识整理及整文问答使用知识库配置，页面问答/OCR 使用聊天配置，翻译使用翻译配置。不改写已保存凭据；也可只额外启用整文问答的 DSH 路由。
- 支持的地址、模型和图片能力由 `demo/electron/dsh-capabilities.ts` 统一定义，设置页与主进程使用同一份能力表：

| 官方地址 | 模型 | 图片输入 |
| --- | --- | --- |
| `https://api.deepseek.com`（可带 `/v1`） | `deepseek-flash` | 支持 |
| 同上 | `deepseek-v4-flash`、`deepseek-v4-pro` | 不支持 |
| `https://open.bigmodel.cn/api/paas/v4` | `glm-4.6v` | 支持 |
| 同上 | `glm-4.5-air`、`glm-4.7-flashx` | 不支持 |

- 图片只接受内嵌 PNG/JPEG，禁用任意远程图片 URL；页面答疑与 OCR 必须选择图片模型。
- 显式联网搜索也进入同一后台队列，由固定智谱搜索工具执行；它不是放开 DSH Agent 自由浏览或任意工具权限。Windows 共享浏览器通过桌面宿主执行，无需安装 DSH。
- 不向公网提供 DSH RPC，不在客户端网页放置主机命令接口。无桌面桥接或 DSH 失败时明确报错，不静默回退 API。

## 配置检查与运行诊断

- 设置页逐项显示翻译、图片答疑、OCR、知识整理和全文问答实际使用的后端。保存前检查官方地址、模型白名单、图片能力和各自密钥；错误定位到对应栏目与字段。
- 本机自检检查四个 DSH 包的入口文件、固定版本和安装目录中的 Node 可执行文件；要求 Node 22.13 或更新版本。缺失、版本不一致或自检未完成时不能保存 DSH 设置。自检不访问模型服务，不验证账户余额或鉴权。
- 点击「测试当前栏目 DSH 连接」才发送一次短请求（最多 32 个输出 token，20 秒执行超时）；可取消，关闭设置也会取消。测试不自动改写配置。
- 固定版本暂不支持 `temperature` 和 `responseFormat`。页语 DSH 调用显式使用供应商默认采样，并自行解析、校验整理 JSON；直接传入这两个参数会返回 `unsupported_parameter`，不会静默忽略。
- 请求报告排队、启动、执行耗时及任务类别，经 `onDshStatus` / `onTiming` 传给调用方；知识生成接入原有分层诊断。耗时字段不包含密钥或请求正文，DSH 层重试数当前为 0；领域层的输出修复/重试另行记录。这不是完整的持久化审计或费用统计系统。
- 运行时缺失、模型不支持、鉴权、限流、网络、排队超时、执行超时、取消和协议错误使用固定错误码跨 worker/IPC 传递，不向界面透传供应商原始错误内容。

## 安装与构建

宿主需要 Node.js 22.13+、npm，执行：

```sh
cd demo
node scripts/install-dsh.mjs
pnpm desktop:build
```

安装脚本将官方 `@deepseek-ai/dsh`、`dsh-sdk-client`、`dsh-llm-pi-ai` 和 `dsh-attachment-local` **均锁为 `0.1.7-rc.2`**，安装至用户目录 `.local/opt/yeyu-dsh-runtime-0.1.7-rc.2`，禁用 npm lifecycle scripts，并保存安装时的 Node 可执行文件供桌面快捷方式使用。不要将旧版 SDK 和新版 CLI 混装；这会导致 scope carrier 检查不兼容。运行时会验证包版本。新版 SDK 必须使用 `profile/patches/processCwd` 启动选项；旧式 `command/args/cwd` 会被忽略，错误进入有工具的默认 profile，测试明确防止此回归。

桌面构建同时产出 `app.asar` 中的后台 worker 和独立 `resources/client` 前端；更新部署时必须同时更新，不能只复制 asar。

## 调度与后台生命周期

- 全局最多 4 个 DSH 调用并行，后台整理和预取合计最多占 3 个，保留 1 个位置供交互请求使用。默认顺序为交互 → 后台整理 → 预取，同类按入队先后；等待达到 30 秒或连续启动 8 次交互任务时，等待任务会获得调度机会，不抢占已经运行的请求。
- 最多 32 个在途请求，序列化请求数据合计不超过 64,000,000 字节。**排队最多 180 秒；单次执行默认 180 秒**。显式执行/连接/流空闲超时参数须为 1–600,000 ms；连接计时从运行时就绪后开始。这些限制不是整份 PDF 的完成时限。
- 整理任务的阶段和控制状态保存在课程记录中，全局任务中心可暂停、继续、取消、重试。暂停/取消先保存意图再中断，保留 PDF、已完成成果和有效层级缓存；失败任务不自动循环重试。
- 桌面主进程监督独立隐藏执行窗口，阅读 UI 重载不拥有其生命周期；执行窗口异常时最多自动重建 3 次，超限明确提示重启应用。退出应用会停止执行，下次启动恢复未完成任务；手动暂停/取消状态不会被自动恢复为运行。网页模式仍依赖打开的页面和目录授权。
- DSH 的内存请求队列不跨进程重启恢复；恢复来自持久化课程阶段和有效缓存，未完成的模型请求会重新发起。后台窗口也不等于常驻 DSH 模型会话，每次模型调用仍独立建立 worker 与临时目录。

## 数据及安全边界

- 每次调用单独生成临时 DSH_HOME、工作目录和会话，只传入本次文字和可选图片；不向 DSH 提供真实课程路径。附件存储仅供 SDK 内部图片处理，不开放文件工具。
- SDK minimal profile 默认带 shell。页语显式禁用 Bash、PowerShell、PTY、subprocess 工具、MCP 资源及附加会话日志/API 扩展；保留官方 invariant 检查，sandbox policy 设为 read-only。
- 这是关闭工具能力与目录隔离，不是操作系统级恶意代码沙箱；官方运行时依然是本机受信程序。
- API key 经 worker stdin 和模型进程私有环境传递，不出现在启动参数、应用日志或前端进度中。资料仍会发送至用户配置的 DeepSeek 或智谱官方服务。
- IPC 校验应用 origin、主 frame 和窗口角色；只有主窗口可发任务控制，只有后台执行窗口可发布后台快照。课程存储和 DSH 调用只向对应受信角色开放，不接受任意同源窗口。
- 取消、所属执行窗口失效和退出时终止对应模型任务并清理临时文件；主阅读窗口重载只取消它自己拥有的请求，不取消独立后台窗口的整理任务。课程写入继续经过版本检查和串行锁。
- 结果须收到匹配的 prompt 回执和明确完成事件。截断标记不会当成完整 JSON 保存。API 和 DSH 使用不同知识缓存空间，切换后不会将 API 缓存冒充 DSH 产物。

## 缓存与性能边界

同课程答疑共享稳定排序、有长度上限的课程摘要、资料索引和术语前缀；页面/文档会话继续独立，不把全部历史塞入一个无限增长的对话。Windows 宿主问答和桌面采用同一课程上下文构造器。相同前缀有利于服务商的自动缓存，但“同一个项目/对话”本身不保证命中，也不保证最低费用。

本地已有 PDF 成果、翻译和 OCR 缓存继续复用；队列中完全相同的并发请求只执行一次，按模型、账户、输入及参数隔离，失败/截断结果不复用。完成后的显式重新生成会发起新调用，不被队列复用层拦住。

DSH 是执行框架，不会提升模型本身的 token 生成速度，也不能绕过输出上限。页语现有的分块、有限重试和预算控制依然必要。复杂 PDF、OCR、多文档课程合并及深度思考可能超过三分钟，必须以实测报告为准。

共享阅读器打开翻译面板或翻页后先读取已发布译文，缺失时自动请求宿主，默认不绕过缓存。页面/语言稳定 350 ms 后才发起请求，隐藏的响应式面板和无 AI 权限的会话不自动生成；离开页面取消旧请求，迟到结果不覆盖当前页。失败或主动取消后不循环重试，保留手动重试；只有“重新翻译”已有译文才明确绕过缓存。

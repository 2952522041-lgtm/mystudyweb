# PDF 导入性能与同步排障

导入分为“PDF 已保存”和“AI 整理完成”。前台只检查内容指纹、解析页数并保存 PDF 和课程清单，随后即可阅读；OCR、单篇成果和课程汇总作为独立后台任务处理。不能把“已保存”误报为“AI 成果已完成”。

## 0.2.1 更新（2026-10-05）

快速模式保留完整已校验分块正文，最终只重算概述与脑图；无术语表的快速文档最终输入可用52KB，实际完整消息仍受64KB限制。DSH在收到首事件后不再按SDK通知静默误判卡住，仍保留真实网络idle、总时限及取消。课程按轮转调度；阅读器仅在可见译文面板自动翻译和预取。

同一59页样本的有效基线/本轮分别226.302秒与136.007秒，23/14次请求，仅各一次，含随机重试差异。抽查发现两版都有表格与图像文字提取局限，新版脑图导航粒度也不同；不能称为等质无损或通用三分钟保证。测量范围、哈希、质量抽查和桌面验证详见[本轮验收](validation/2026-10-05-speed-ux/REPORT.md)。以下历史测量保留原日期与条件。

## 快速保存与后台队列

- 可多选 PDF，先逐份保存原文件；没有配置 AI 也能保存、打开。关闭总结、脑图和课程汇总三个选项时，不创建 AI 任务。
- 每份资料的 processing 写入 course.json，记录 document/course 阶段、queued/running/failed 状态、原始选项及错误。没有 processing 表示没有待执行任务；需结合成果标记判断是否生成过成果。
- 单篇 digest 和选中的成果独立提交，随后才排队课程汇总。一批新文档先全部处理，课程统一汇总一次；汇总失败不撤销 PDF 或单篇成果，重试不会重新分析已经保存的单篇。
- 阅读器与课程库保持挂载，后台整理不占用前台导入/阅读锁；短暂文件写入按课程串行，AI 请求期间可以保存其他 PDF。
- 关闭 App 会中止当前请求，队列仍在磁盘；重开自动接续 queued/running，failed 需点击资料卡“重试”。浏览器目录权限失效时须重新授权。不会关机后继续运行，也不无限自动重试失败请求。
- 课程列表与 MCP 文档状态显示后台阶段；MCP 导入返回只确认保存/排队，不保证 AI 成果已经完成。

## 本次改进

- 提取/OCR 最多同时处理两页，返回结果仍按原始页序排列。取消信号传到图像渲染和 OCR 网络请求，停止排队并等待正在执行的页面清理。
- UI 和 MCP 复用同一份导入进度；`yeyu_get_state` 的 `courseLibrary.importProgress` 给出文件、阶段、百分比、总耗时与当前阶段耗时。百分比不会因并行任务乱序完成而倒退。
- MCP 本机 HTTP 通道使用明确的长请求时限，避免 Node fetch 默认 300 秒等待响应头超时，而 Electron 仍在执行 30 分钟导入的矛盾。
- Linux 自动读取 XDG 系统文档目录，不再默认假设用户使用英文 `Documents`；显式控制文件和工作区环境变量仍优先。
- 课程综合在文档级元数据及身份表保留文件名，不在每条概念来源中重复；逐条来源保留 documentId 和原页码，本地校验时恢复文件名。紧凑输入能落入既有最终预算时直接综合，避免仅因重复元数据产生中间归并，完整请求仍接受字节预算与来源范围校验。
- 关系字段示例使用单个合法标签，单独声明可选值，避免把竖线分隔的枚举当成输出值；不合规关系仍拒绝，并在错误中列出实际标签和端点。
- 对模型写反的“包含”关系，仅在唯一节点 ID 与显式 parentId 能证明方向时本地交换端点，继续执行来源、层级和循环校验；不会删边、改变正文或为修复格式新增 AI 请求。
- 分批课程综合只携带本批使用的文档身份映射，避免无关新增文档破坏旧批次缓存；关系记录携带唯一已知端点的原始来源范围，分批后仍保留页码间隙，不会推测缺失来源为第 1 页。
- 课程总图明确作为跨文档主题索引，材料充分时目标为 24–36 个节点（少量材料更少），分支与叶子合计仍受原有 60 节点硬上限约束；保留单篇完整成果，不用截断数组处理超限。超限错误显示实际数量，减少模型把上限误作目标后反复重试。
- 重名节点即使没有深度或宽度超限，也可按原始章节、页码与节点 ID 本地区分；结构修复漏写重命名时保留原名后走同一校验与规范化流程，不删除事实或额外请求全文。
- 知识库设置新增默认「快速整理」与可选「深入推理」。仅官方 GLM-4.6V 的普通文档/课程综合在快速模式关闭额外 thinking；结构修复保留模型默认推理。其他模型和代理不发送此参数。快速与深入的最终层缓存隔离，深入不会误用快速生成结果；快速可以复用已验证的旧深入文档成果，分块与中间索引仍共享缓存。

并行主要缩短扫描件逐页等待。文档分析与课程综合依赖 AI 服务，仍可能花费数分钟；没有更换用户模型、缩减材料、跳过校验或伪造总结。

## 冷缓存性能复测（2026-09-29）

- 修复文档综合的预算判断：完整分块结果在 36 KB 最终预算内时直接综合，不再先按 24 KB 中间预算展开记录、重复元数据并触发额外归并。实际发送前的完整消息预算和来源校验保持不变。
- 初次导入中，只有一个通过完整校验的 AI 文档成果、且没有用户节点时，课程直接复用该文档的结构和证据，省去重复的课程 AI 综合。多文档、旧结构、不完整成果和用户节点均回退原流程；手动重新生成仍调用模型。
- 提示词要求紧凑 JSON，仅去除格式空白，不压缩事实、公式、表格或来源。
- 每个知识请求记录响应头、首个内容、总耗时、输出字符数和完成状态；不记录密钥或正文。连接 30 秒、流停滞 45 秒会报错；它们不是“180 秒成功”的替代品，持续输出不会被总计时强制截断。

复测脚本复用真实桌面端设置，调用真实模型，使用独立的内存成果/分层/OCR 缓存与临时内存课程。原 PDF 只读，已有成果不覆盖。模型服务自己的 prompt cache 不受客户端控制。计时含读取本机已上传的 PDF、提取、全部 AI 请求及内存成果提交，**不含 Windows 上传网络和磁盘写入时间**；因此超过 180 秒即可判定端到端目标不达标，但小于 180 秒不能独自证明 Windows 上传也达标。

桌面端启用仅本机调试端口 `9223` 后，在 `demo/` 执行（会产生实际模型用量）：

```bash
node scripts/benchmark-pdf.mjs windows传入test CAN总线入门书.pdf /tmp/yeyu-can-report.json
```

脚本仅输出计时、请求长度和成果计数，密钥不离开 renderer。退出码 0 表示完整成功且不超过 180 秒，1 表示失败，2 表示成功但超过目标。12 分钟保护线仅用于停止异常测试，不计为成功。当前完整成功要求摘要、脑图以及有效课程候选（或已合并成果）均存在；候选不会自动发布。

实测文件：`CAN总线入门书.pdf`，49 页、1,906,878 字节、30,344 个提取字符，0 页需要 OCR。模型为官方接口 `glm-4.6v`，快速模式，全部请求关闭 thinking。两次均使用空应用缓存：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 完整成功耗时 | 428.735 秒 | 405.115 秒 |
| AI 请求次数 | 7 | 4 |
| 读取、检查、提取完成 | 287 毫秒 | 304 毫秒 |
| 最终文档综合一次请求 | 110.088 秒 | 283.032 秒 |
| 该次输出 tokens | 8,611 | 8,529 |
| 最终成果 | 摘要、脑图、课程合并成功 | 摘要、脑图、课程合并成功 |

修改后单文档复用命中，额外两次中间归并和一次课程综合均已省去。模型输出并不确定，两次成果分别为 45/41 个摘要节、33/28 个概念；只验证结构、来源与成果完整性，不把它们宣称为逐字一致。尽管请求减少，第二次最终综合输出规模相近却慢了约 2.57 倍，约 30 tokens/s（含请求首字等待），单次就超过 180 秒。**三分钟验收不通过**，不能把本次代码优化交付为达标，也不能仅靠并行更多请求解决这一条串行请求的耗时。仍需更快的模型/服务端吞吐，并在相同文件、相同验收条件下重新测量；没有擅自替换用户模型。

## DeepSeek 输出截断修复（2026-09-29）

`deepseek-flash` 使用官方 `https://api.deepseek.com` 时，旧的通用 8192-token 请求额度并不代表模型真实上限，而且未发送思考开关会启用服务商默认思考。本机故障文件 `xid-12544620_1.pdf`（59 页）的两次真实请求均返回 `completion_tokens=8192`、`reasoning_tokens=8192`、`finish_reason=length`，正文字符数为 0；不能把它解释成材料太长或模型无能力。

- 官方 DeepSeek Flash / V4 Pro 接口接入快速整理：分块、中间层以及快速模式最终层明确发送 `thinking.type=disabled` 和 JSON 格式。深入模式最终层与结构修复仍保留默认思考；自定义代理和未知型号不发送供应商私有参数。
- 官方 DeepSeek 的普通知识请求使用应用预算 32768 tokens，中间索引仍保留 8192 上限；该数值是应用预算，不声称是供应商最大值。额度不会强迫模型生成同等长度。
- `finish_reason=length` 不论 JSON 能否解析均丢弃，不写入缓存。现在与输入超限一样触发有界拆分：只重算失败分块/批次，保留所有文字、页码、成功层和原文件；过小、不可拆分、达到深度上限或归并不再缩小时明确失败，不无限调用。
- 分块报错不再声称“整份文档无法一次综合”。输入超限与输出截断的诊断分别记录，鉴权/额度/限流错误不触发拆分。

依据：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/)。

修复后同一 59 页文件冷缓存实测：130.893 秒，0 页 OCR，摘要、脑图和单文档课程合并均成功；全部分块的思考输出为 0，3 个初始分块分别耗时 16.723、21.953、18.181 秒。计时范围仍是上面的隔离内存基准，不含 Windows 上传网络，不代表任意大小 PDF 都有三分钟保证。

## 通过现有 MCP 操作

在 `demo/` 下构建后、保持页语桌面端运行：

```bash
pnpm mcp:build
node scripts/yeyu-tool.mjs state
node scripts/yeyu-tool.mjs import course-name /absolute/path/lecture.pdf
node scripts/yeyu-tool.mjs import --wait course-name /absolute/path/lecture.pdf
```

脚本使用 stdio MCP，不直接写课程数据库。默认快速保存并排队；`--wait` 每 15 秒按 documentId 查询后台任务，失败退出但不重复提交导入。自定义工作区可设置 `YEYU_WORKSPACE_ROOT` 或 `YEYU_MCP_CONTROL_FILE`；不要把控制文件中的令牌复制到日志或仓库。

如果导入调用断开或超时，先查 `importProgress.active`、课程清单和文件哈希。运行中的导入不能重复提交；已提交的 PDF 应通过指纹去重。尚未完成的资料不能仅凭下载成功就标记为同步成功。

# 导入速度与阅读体验（2026-10-05）

基线：`69be02a`。实现以 DSH 执行局部任务、主 Agent 审查集成为准。

## 验收目标

- 比较同 PDF、相同配置的真实生成请求，记录提取、分块、最终综合及课程候选的耗时。区分冷缓存、热缓存、模型分段基准与生产落盘流程，不把内存测试称为端到端。
- 快速整理复用全部校验后的分块章节，最终模型综合整体概述和脑图，减少重复输出正文。深入模式仍重新综合章节。两模式隔离缓存，保留来源、截断拒绝、取消和结构校验。
- 亲自走通创建课程、导入、后台任务、阅读与来源跳转、审阅、设置及返回继续阅读；记录遇到的问题并修复。
- 单元、浏览器、类型检查和桌面验证通过；逻辑批次提交，产物记录版本。

## 视觉方向

采用纸张与文件夹的阅读工作台：内容左对齐，墨蓝页边标识定位课程，主要操作是“导入 PDF”，管理入口收起。中文使用本机 Noto Sans CJK SC / 微软雅黑与系统无衬线，不请求外部字体；标题 28px/600，正文 14–16px，辅助信息至少 12px，长文本有舒适行高。

| 色彩 | 值 | 用途 |
| --- | --- | --- |
| 工作台 | `#F3F6F8` | 页面背景 |
| 纸张 | `#FFFFFF` | 阅读区域 |
| 墨色 | `#243746` | 标题、主要文字 |
| 书签蓝 | `#315D7C` | 操作、选中、焦点 |
| 次要文字 | `#687789` | 日期、页数、说明 |
| 分隔线 | `#DDE4E9` | 导航、资料行边界 |

方案 A（采用）：

```text
页语        课程知识库 / PDF 阅读器          设置
课程目录 | 课程名                         导入 / 管理
可滚动   | PDF数、节点数、更新日期（单行）
         | 继续学习：最近阅读的文档
         | 搜索 / 待审阅提示
工作区   | 总结 / 脑图 / 资料 / 笔记 / 历史
         | 正文、来源或资料行
```

方案 B（舍弃）：首屏仪表盘式统计卡片、共享横幅、管理卡片后接课程内容。实际 1213×871 基线截图中总结位于首屏底部，与阅读任务不符。

审查：不采用新插画、大标题营销区、四张彩色指标卡或装饰渐变。将视觉重点放在课程目录的页边选中标记与连续阅读内容，管理信息按需展开。保留响应式切换、可见键盘焦点和原有无障碍对话框。

设计参考：已阅读并安装 [Anthropic frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)。

## 本地验证过程

- 真实窗口：课程内容 tabs 从约 y=762 前移到 y=476（1213×871，后续还收起资料页的继续学习区域）。资料页已检查 1024×768、390×844、1100×600，无主内容横向溢出；窄屏保留课程选择器。
- 在隔离工作区通过 UI 创建 20 门测试课程，总计 21 门。1100×600 时目录可独立滚动，末项可达，底部“工作区与共享”底边为584px。
- 课程页设置与导入框内的设置均可打开知识库 AI 栏目；关闭设置返回导入框后，已选 PDF 保留。最初一次“丢失文件”报告来自测试误触隐藏阅读器入口，已撤销，后续测试只操作可见入口。
- 阅读器回归发现收起右栏后打开成果时的分栏注册竞态；已验证连续拖动、隐藏载入恢复和显式打开成果。实时拖动比例与默认恢复比例分离，避免面板重新注册。
- 调度回归发现课程 ID 仅由毫秒时间戳生成，快速创建课程会重名并覆盖队列映射；新课程加入 UUID，旧课程 ID 不变。
- 首轮全套 938 项测试：935通过、3失败。失败为课程 ID 碰撞和两项旧文案断言，修复后针对性20项通过；最终全套扩展至957项并全部通过。
- 两次旧版本真实模型基线均失败（49页约91.7秒，59页约217秒），不能作为提速成功证据。前者中间归并校验失败；后者结构修复等待中被超时中断。已修正 SDK 不转发实时片段与应用通知空闲计时不相容的问题；真实 worker + mock SDK 的启动、等待、SDK idle、总时限和取消测试通过。
- 全套第二轮 955/955 通过，无失败或跳过；随后实机补充问题继续修复，最终全套另记录。
- 实机更新后遇到 HTTP 缓存引用旧 lazy chunk，主窗口硬刷新后隐藏 worker 仍失败。启动仅清 HTTP 缓存、内置静态服务 `no-store`、缺失资源返回404；真实预热旧缓存后跨重启验证课程、localStorage、IndexedDB 和模拟认证 cookie 保留。
- 2页示例经过真实后台队列在重试后约17.2秒保存摘要/脑图/课程候选；预览有独立滚动，接受后课程总结出现。此计时不包括之前排查旧脚本失败的时间，也不声称冷缓存端到端。
- 实机候选已落盘而课程页停留在上一revision，复现为连续 IPC 通知的第二个load被effect重订阅清理丢弃。稳定订阅及单调revision保护已通过受控乱序回包回归。
- 查看总结仍触发翻译及下一页预取，且返回课程没有取消。现在仅在可见译文面板执行这两个流程，切换/隐藏/收起取消，缓存结果保留；真实浏览器回归覆盖。
- 59页新版内存模型基准完整成功约136秒；旧版首次成功受短暂自动翻译干扰，另做干净重测。两者统一使用修复后DSH传输层，服务端缓存不可控；不能用原来的失败样本计算提速比例。
- 原文、凭据、完整模型输出和截图只保留在私有测试目录 `/tmp/yeyu-speed-ux-20261005`，不进入仓库。最终报告应仅记录安全指标，区分模型内存基准和真实后台落盘流程。
- 最终957/957通过。干净模型对照、质量限制、真实多文档候选的重启/保留原成果、脑图窄栏修复及桌面产物状态统一记录于上述验收报告。

# DSH 协作开发

主 Agent 统筹，DSH CLI 执行边界清楚的编码子任务。用户已授权一般派发，无需重复确认分工；本次用户指令优先。该授权不扩展任务范围或运行环境权限。

## 分工与任务包

- 主 Agent 保留当前模型，理解现有代码、设计接口、拆分任务，掌握共享状态、存储、权限与并发风险；负责最终审查、集成、必要验证及按仓库约定提交。
- 优先派发纯函数、局部组件、明确接口适配、针对已定义行为的测试等独立任务。微小修改、强耦合设计或高风险迁移由主 Agent 直接完成；不用为满足派发形式额外制造工作。
- 每项派发创建独立临时工作目录，只复制必要源码、类型和测试上下文，避免多个执行者改同一份文件。不要复制凭据、真实用户数据或完整个人配置。临时目录是交付边界，不是操作系统沙箱。
- 在目录内写 `TASK.md`：目标、输入输出契约、允许改动的相对路径、禁止改动项、可用依赖、测试命令及验收标准。要求执行者只在该目录实现和运行指定测试，不访问其他项目、不安装依赖、不改变环境权限、不执行提交或发布。
- 最终报告要求列出变动文件、测试命令与实际结果、未解决项。准备任务时记录源文件版本或摘要；集成前确认原文件未被其他工作改动。

## 使用本机 CLI

使用当前环境已安装的 `dsh` 或用户明确指定的可执行文件，沿用现有用户认证、模型和 profile 配置。不要猜测模型名、价格、速度或 CLI 参数，不为任务安装/升级 DSH，也不添加插件、工具权限或配置覆盖层。

首次使用或执行文件版本变化时，检查 `dsh --profile headless --help` 和该安装的 README。本机已验证的调用形式是：

```sh
dsh --profile headless 'Read TASK.md, implement the scoped task, run its tests, and report changed files, actual results, and remaining issues.'
```

headless 接受任务文本，创建新会话，向 stderr 输出推理过程、向 stdout 输出最终回答后退出；调用时的工作目录是默认 workspace。不要把应用内无工具的 `sdk-minimal` 接口当作 CLI 编码执行者。

`--help` 也可能初始化 profile 并写入 `DSH_HOME`。仅需查帮助且默认配置目录不可写时，可使用空的临时 `DSH_HOME` 查帮助；正式任务仍使用已登录的默认环境或用户指定运行环境。不要通过复制认证文件、打印环境变量或凭据来修复认证问题。

## 有界运行与接管

从准备好的临时目录启动命令（设置执行工具的 `workdir`）。使用已验证的超时工具约束整次调用；本机 `timeout --help` 已确认以下形式：

```sh
timeout --signal=TERM --kill-after=10s 600s dsh --profile headless 'Read TASK.md, implement the scoped task, run its tests, and report changed files, actual results, and remaining issues.' > dsh-run.log 2>&1
```

- 每次启动前确定期限；上例为 10 分钟，按任务复杂度与用户约束缩短或调整。不要使用 `--foreground`，它会使子进程脱离 timeout 的超时处理范围。
- 将临时目录设为仅当前用户可访问，日志设为仅当前用户可读写。用短时间片轮询进度，记录退出状态、实际耗时和日志位置；不要把原始日志、认证信息或模型推理直接转发给用户。
- 正常退出只说明进程结束，不证明任务完成。超时状态通常为 124，强制终止为 137；其他非零退出也要检查。停止该次调用及其仍在运行的任务进程，保留可审阅产物，不能因出现“完成”字样忽略失败状态。
- 对可修复的实现问题，把失败证据和明确修改目标写回任务包；最多两次纠正后由主 Agent 接手。认证缺失、命令不可用、执行权限被拒绝或持续无产物时，说明实际限制并由主 Agent 完成，不循环安装、切模型或修改 DSH 内部工具授权。
- 环境不提供兼容的超时工具时，使用已验证能终止任务进程的执行机制；没有可靠的有界执行方式则由主 Agent 接手，不发明 DSH 的超时参数。

执行工具的沙箱若阻止访问用户已授权使用的认证或运行目录，应遵循上层规则申请必要执行权限；不复制认证或绕过审批。申请被拒绝或无法提供权限时，由主 Agent 接手。

## 审查、集成与交付

主 Agent 检查真实文件及 diff，确认只有允许范围内的修改；审查异常分支、数据处理、权限与并发影响。独立运行验收测试，不能只引用 DSH 的完成声明或测试报告。拒绝未完成的代码、无关改动、凭据和任务日志进入仓库。

确认源文件没有并行变化后，只集成审核通过的产物，运行与变更相称的仓库检查并按项目要求提交。向用户简要说明 DSH 实际承担的工作、主 Agent 的独立验证及仍存在的限制；不把 CLI 执行成功表述成整个项目验证通过。
